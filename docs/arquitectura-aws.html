Arquitectura de referencia

Arquitectura AWS · Sistema de Comités Paritarios

Despliegue sobre Linux con API y SPA desacoplados, base de datos administrada y almacenamiento de objetos. Alta disponibilidad Multi-AZ, cifrado de extremo a extremo y aislamiento de red por VPC. Una sola instalación sirve a todas las empresas cliente y a los organismos que la ofrecen con su propia marca, con los datos aislados, en una cuenta AWS propia del proveedor: sin dependencia de ninguna mutualidad. Diseño preparado para la decisión de residencia de datos (Ley 21.719).

Residencia de datos (decisión crítica): AWS aún no tiene región en Chile (anunciada para fines de 2026). Hoy la más cercana es South America — São Paulo (sa-east-1), lo que implica una transferencia internacional bajo la Ley 21.719 y exige salvaguardas (cláusulas tipo). Alternativas: esperar la región de AWS en Chile o usar un proveedor con región local (Azure Chile Central). Debe informarse a las empresas cliente. Definir con legal antes de fijar la región.
1

Flujo de una petición

Usuario→ Route 53→ CloudFront + WAF→ S3 (SPA) / ALB→ ECS Fargate (API)→ RDS · Redis · S3

La identidad se valida con Cognito (token). Las tareas asíncronas (recordatorios de reuniones, alertas de vencimiento, cierre de actividades) las dispara EventBridge sobre Lambda, que notifica por SES.

2

Decisiones clave

Alta disponibilidad

  • RDS Multi-AZ con réplica y failover automático.
  • ECS Fargate en ≥2 zonas con Auto Scaling.
  • ALB reparte y aísla instancias caídas.

Seguridad

  • Base de datos sin salida a internet (subred privada).
  • Cifrado en reposo (KMS) y en tránsito (TLS).
  • Secretos fuera del código; acceso por rol IAM.
  • Datos sensibles de salud con acceso reforzado.

Escalabilidad

  • API sin estado: escala horizontal con la demanda.
  • Sesión en Redis → sin dependencia de instancia.
  • CloudFront descarga el tráfico estático.

Costos y operación

  • Fargate/Lambda: se paga por uso, sin servidores.
  • Sin licencias Windows/SQL Server (stack Linux).
  • IaC (Terraform / CloudFormation) para reproducir.
3

Multiempresa e independencia

  • Una instalación para todos los clientes: cada registro pertenece a una empresa (empresa_id) y PostgreSQL aplica Row-Level Security, así ninguna empresa ve datos de otra.
  • Activos propios: cuenta AWS, dominio (app.paritario.cl, ejemplo), correo SES con SPF/DKIM/DMARC del dominio propio, identidad en Cognito propia y repositorio de código del proveedor.
  • SSO opcional: una empresa cliente puede conectar su propio proveedor de identidad (Entra ID, Google) vía SAML/OIDC, sin que la plataforma dependa de él.
  • Reproducible: toda la infraestructura en IaC (Terraform o CloudFormation), lo que permite moverla de región o de cuenta sin rehacerla.
4

Marca blanca para organismos

  • Dominio del organismo: el organismo apunta un subdominio suyo (p. ej. comites.organismo.cl) a CloudFront con un registro CNAME; AWS Certificate Manager emite su certificado sin costo. La aplicación reconoce el dominio de entrada y carga la marca de ese organismo (nombre, logo, colores).
  • Correos con su remitente: SES verifica el dominio de envío del organismo (SPF, DKIM y DMARC), así las notificaciones salen a nombre del organismo.
  • Inicio de sesión con su portal: Cognito federa el proveedor de identidad del organismo (SAML u OIDC), para que sus usuarios entren con la misma cuenta que ya usan.
  • Integraciones: listado de adherentes por SFTP (AWS Transfer Family) o API (API Gateway); intercambio con su programa de certificación por API. Las credenciales quedan en Secrets Manager.
  • Instalación dedicada (opcional): si un organismo, por ejemplo un servicio público, exige separación física o residencia en Chile, el mismo código de infraestructura (IaC) levanta una instalación exclusiva en otra cuenta o región, sin cambiar la aplicación.
