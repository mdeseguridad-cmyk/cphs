Arquitectura de referencia

Arquitectura AWS · Sistema de Comités Paritarios

Despliegue sobre Linux con API y SPA desacoplados, base de datos administrada y almacenamiento de objetos, cifrado de extremo a extremo y aislamiento de red por VPC. El diagrama muestra la instalación del piloto, escrita en Terraform (infra/): la API corre en AWS Lambda, sin balanceador ni servidores encendidos. La sección 5 explica qué se agrega para producción. Una sola instalación sirve a todas las empresas cliente y a los organismos que la ofrecen con su propia marca, con los datos aislados, en una cuenta AWS propia del proveedor: sin dependencia de ninguna mutualidad. Diseño preparado para la decisión de residencia de datos (Ley 21.719).

1

Flujo de una petición

Usuario→ CloudFront→ S3 (SPA) / URL de Lambda→ Lambda (API)→ RDS · S3

El usuario se identifica con Cognito y el front envía su token en el encabezado X-Token-Usuario, junto con el SHA-256 del cuerpo en x-amz-content-sha256. CloudFront firma la llamada a la función (usa Authorization para eso), que nadie más puede invocar. La API valida el token, abre la transacción indicando qué usuario opera y la base aplica la seguridad por fila.

Lambda (API)→ S3 operaciones/trabajos/→ Lambda (trabajos)→ SES · Cognito

La API no tiene internet. Para enviar un correo o crear un usuario deja un trabajo en S3; la función de trabajos lo ejecuta. Los documentos se suben y bajan directo entre el navegador y S3 con URL firmadas.

Scheduler 07:30→ Lambda (API)→ Lambda (trabajos)→ Servicio del cliente→ S3 importaciones/→ Lambda (API) → RDS

Sincronización diaria de empresas (o contratos) y centros de trabajo desde los servicios del organismo o de la empresa cliente. La función de trabajos usa las credenciales del cliente guardadas en Secrets Manager; la API importa con funciones de la base que solo tocan las empresas de esa integración y marcan bajas sin borrar. Si el usuario entra con el SSO de su cliente, Cognito recibe su RUT, perfil y contratos, y la API concilia sus accesos en cada ingreso.

2

Decisiones clave

Disponibilidad

  • Lambda corre en dos zonas sin configuración adicional.
  • Base single-AZ en el piloto, con respaldos diarios; Multi-AZ en producción.
  • Protección contra borrado en la base y en Cognito.

Seguridad

  • API y base sin salida a internet; S3 solo por un endpoint limitado a los buckets del sistema.
  • La API entra a la base con tokens de IAM: no hay clave de aplicación guardada.
  • Cifrado en reposo y en tránsito de punta a punta (TLS verificado hasta la base).
  • La función de trabajos no llega a la base; la API no puede enviar correos ni crear usuarios.
  • Datos de salud solo para la empresa y el comité (seguridad por fila); la base rechaza una investigación sin esa marca.
  • Bitácora de accesos a datos personales separada por empresa: solo su administrador la consulta (pantalla con filtros y descarga en CSV, que también queda registrada; cada entrada guarda la IP del visitante según CloudFront y su navegador), y la aplicación no puede modificarla (el administrador técnico sí: ver sección 5).

Escalabilidad

  • Lambda escala sola; la concurrencia se limita para proteger la base.
  • API sin estado: con tráfico sostenido, la misma imagen pasa a ECS Fargate con balanceador.
  • CloudFront descarga el tráfico estático.

Costos y operación

  • Piloto ≈ 28 – 38 USD/mes; la base es casi todo el costo.
  • Sin balanceador, NAT Gateway ni IP públicas permanentes.
  • Encendido programado de la base (días hábiles o fines de semana).
  • Sin licencias Windows/SQL Server (stack Linux).
  • Toda la infraestructura en Terraform, con pruebas.
3

Multiempresa e independencia

  • Una instalación para todos los clientes: cada registro pertenece a una empresa (empresa_id) y PostgreSQL aplica Row-Level Security, así ninguna empresa ve datos de otra.
  • Activos propios: cuenta AWS, dominio (app.paritario.cl, ejemplo), correo SES con SPF/DKIM/DMARC del dominio propio, identidad en Cognito propia y repositorio de código del proveedor.
  • SSO opcional: una empresa cliente puede conectar su propio proveedor de identidad (Entra ID, Google) vía SAML/OIDC, sin que la plataforma dependa de él.
  • Reproducible: toda la infraestructura está en Terraform (infra/), lo que permite moverla de región o de cuenta sin rehacerla.
4

Marca blanca para organismos

  • Dominio del organismo: el organismo apunta un subdominio suyo (p. ej. comites.organismo.cl) a CloudFront con un registro CNAME; AWS Certificate Manager emite su certificado sin costo. La aplicación reconoce el dominio de entrada y carga la marca de ese organismo (nombre, logo, colores).
  • Correos con su remitente: SES verifica el dominio de envío del organismo (SPF, DKIM y DMARC), así las notificaciones salen a nombre del organismo.
  • Inicio de sesión con su portal, con rol: Cognito federa el proveedor de identidad del organismo o de la empresa cliente (SAML u OIDC). Su sistema envía el RUT, el perfil y los contratos del usuario; cada perfil equivale a administrador, coordinador o auditor, y el usuario recibe ese rol en las empresas de sus contratos.
  • Empresas y centros desde sus sistemas: cada día se consulta su servicio de empresas o contratos y de centros de trabajo (API o SFTP); cada carga queda registrada con nuevos, actualizados, bajas y errores. El contrato (número de adherente) une a cada empresa con su organismo. Las credenciales quedan en Secrets Manager.
  • Instalación dedicada (opcional): si un organismo, por ejemplo un servicio público, exige separación física o residencia en Chile, el mismo código de infraestructura (IaC) levanta una instalación exclusiva en otra cuenta o región, sin cambiar la aplicación.
5

El piloto prioriza costo bajo. Con más empresas, datos reales a escala o un organismo en marca blanca, se agregan estas piezas sin cambiar la aplicación:
